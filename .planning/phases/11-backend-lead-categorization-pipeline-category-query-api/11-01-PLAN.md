# Phase 11 Plan 01: Implement Backend Category Query Builder and Stats Aggregator

**Phase:** 11-backend-lead-categorization-pipeline-category-query-api
**Plan:** 11-01
**Status:** Ready to Execute
**Requirements Addressed:** LEAD-CAT-01, LEAD-CAT-02

## Objectives
1. Add `category` query parameter handling in `src/app/api/leads/route.ts`.
2. Implement Prisma `where` clause filters for `priority`, `valid`, `unassigned`, and `all`.
3. Compute category counter metrics (`priority`, `valid`, `unassigned`, `all`) in `stats` response using IST timezone bounds.
4. Verify TypeScript compilation.

## Implementation Tasks
1. Edit `src/app/api/leads/route.ts`:
   - Extract `const category = (searchParams.get('category') || '').trim().toLowerCase();`.
   - Calculate IST end of today (`todayEndOfDay`).
   - Append category conditions to `where`:
     - `priority`: `{ branch: { notIn: ['', 'Unassigned'] }, OR: [{ followUpDate1: { lte: todayEndOfDay, not: null } }, { followUpDate2: { lte: todayEndOfDay, not: null } }] }`
     - `valid`: `{ branch: { notIn: ['', 'Unassigned'] } }`
     - `unassigned`: `{ OR: [{ branch: '' }, { branch: 'Unassigned' }, { branch: null }] }`
   - In stats aggregation, query category counts and include in response under `stats.categories`.
2. Verify with `npx tsc --noEmit`.
